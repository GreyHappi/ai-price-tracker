## 2. Recorded notes, objections & corrections (mention in canonical plan where relevant)

- **N-01 — CF Workers webhook analysis (full reasoning preserved):** Telegram bots are polling XOR webhook (`setWebhook` kills `getUpdates`), so a serverless webhook cannot sit beside the polling primary as a "standby command receiver". The backup lane only rescues scrape+notify (plain `sendMessage`, no webhook needed). Commands going silent while the primary is down is a consciously accepted risk. Going 24/7 for commands is a **migration**, not a backup: move the bot wholly to CF Workers webhook (FG Phase-2 design). Reopen trigger lives on D-03.
- **N-02 — GPT 5.6 Sol divergences and outcomes:** base plan (→ D-27 synthesis), git flow (**owner reconfirmed main+dev and no PR**, D-20), MVP breadth incl. OEM (**owner reconfirmed**, D-07), i18n in MVP (owner scope kept; architecture corrections adopted, D-23), story points (kept + actuals, D-18), board generator (**O-07 resolved: defer-until-useful — manual board until ≥5 stories or first drift**, D-22), ADR count (7 core + ledger, D-22), AGENTS/CONTEXT separation (D-22), coverage gates (targeted only, D-17), risk-based review cadence + blind-review inputs (D-19), workspace_id placement (roots only, D-10), task-based AI routing (D-16), AI-extraction quarantine (D-06).
- **N-03 — Fixture test semantics (correction adopted):** a committed HTML fixture test catches *code regressions against known HTML*; it can NOT detect that the live site changed (the fixture is frozen). Live-site drift is caught only by the scheduled live-smoke/health job. TS/LJ overloaded the fixture tests' meaning; wording fixed in D-17.
- **N-04 — "Actions cannot be a scheduler" (TS) softened:** GitHub schedules workflows fine but best-effort — queue jitter (minutes), occasional dropped runs, and public-repo 60-day-inactivity auto-disable. Verdict: unacceptable as the *primary* freshness guarantee, acceptable as a backup lane. A **separate backup-workflow healthcheck**, pinged even on no-op, detects silent disablement; a primary-only check cannot (D-02).
- **N-05 — Poor man's event log + outbox semantics:** `observations` append-only per semantic change gives history where it matters; real event sourcing stays rejected. Outbox-lite is adopted as **at-least-once**, not exactly-once: unique delivery rows prevent duplicate enqueue, but a crash between Telegram acceptance and the local `sent` commit can still duplicate externally (D-05).
- **N-06 — Neon/artifact sizing and privacy guard:** change-only writes protect Neon. Failure diagnostics stay outside Neon, are sanitized and capped, and backup artifacts explicitly expire after 7 days; unsanitized full pages never enter public-repo artifacts (D-12).
- **N-07 — Model economics:** LJ measured DeepSeek V4 Flash ~5.4× cheaper than Gemini Flash-Lite on output tokens; owner's default order stands but is DB-config; the eval set (D-16) decides the final order with data.
- **N-08 — Model naming corrections:** "Gemini 3.7 Flash-Lite" does not exist (Lite is a separate family); "GPT-5.6 Luna Max" is `gpt-5.6-luna` + `reasoning effort: max`. All model IDs re-verified at integration time; never hardcoded.
